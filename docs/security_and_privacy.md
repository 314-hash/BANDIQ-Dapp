# BANDIQ DePIN Bandwidth Node Agent — Security & Privacy Architecture

This document describes the security model, operator privacy protections, cryptographic verification, and safety controls implemented in the BANDIQ Node Agent.

---

## 1. Core Safety Guarantees

### A. Never a Botnet, Hidden Proxy, or Open Relay
- **Zero Inbound Forwarding:** The agent does not open listening ports to the public internet, does not configure UPnP port forwarding, and does not accept proxy connections from external parties.
- **Strictly Isolated Measurement Mode:** In the current version (v0.1.0), all traffic relaying and proxying functionality is disabled by default. The agent operates exclusively in voluntary, outbound measurement mode.
- **Explicit Consent Required:** Even for synthetic bandwidth benchmarking, the agent requires affirmative, explicit operator consent via `bandiq consent grant`. If consent is not present, all measurement loops remain dormant.

### B. Protection of Operator Keys & Wallet
- **No Private Keys or Mnemonic Phrases Requested:** The agent only requests the operator's public EVM wallet address (`0x...`) on Sidra Chain to associate rewards and identify the node operator.
- **Node-Specific Ed25519 Keypair:** The agent generates its own local Ed25519 cryptographic keypair specifically for signing telemetry reports. The private key never leaves the node's local machine and is stored with restricted file permissions (`0600`) in `.bandiq/node_key.json`.
- **Decoupled Identity:** The node's telemetry signing key is completely decoupled from any blockchain wallet private key. Compromising the node cannot compromise the operator's cryptocurrency assets.

### C. Zero Remote Shell or Arbitrary Code Execution
- The agent does not accept, evaluate, or execute shell commands, executable downloads, or arbitrary scripts sent by the backend or any peer.
- The control interface is strictly local (localhost HTTP API) with a fixed, immutable set of endpoints (`/pause`, `/resume`, `/caps`, `/trigger`).

### D. Operator Privacy & Data Minimization
- **No Browsing History or Packet Inspection:** The agent does NOT inspect network packets, parse DNS logs, capture browser history, or read filesystem data.
- **Passive OS Counter Reading:** Interface counters are read through standard OS statistics (`GetIfEntry2` on Windows), which provide numerical byte and packet sums without payload inspection.
- **No PII Collected:** The only metadata attached to reports includes system resource utilization (CPU %, RAM MB, Uptime), network interface name, and benchmark results.

### E. Localhost Administrative Isolation
- The administrative server listens strictly on `127.0.0.1` (loopback).
- The configuration validation engine explicitly throws a fatal error if an operator attempts to bind the admin interface to `0.0.0.0` or a public interface.

### F. No Stealth System Modifications
- The agent **does not modify**:
  - Windows Firewall rules
  - Router or NAT configuration
  - Windows Registry run keys
  - Task Scheduler or system startup items
- The agent runs entirely in user space.

## 2. Cryptographic Attestation & Replay Defense

Every measurement report generated by the agent constitutes a verifiable cryptographic attestation:

1. **Canonical JSON Serialization:** The report fields (excluding signature) are serialized with deterministic, fixed key ordering.
2. **SHA-256 Digest:** The SHA-256 hash of the canonical bytes is computed.
3. **Ed25519 Signature:** The node's Ed25519 private key signs the digest, generating a 64-byte hex-encoded signature (`report.signature`).
4. **Replay Resistance:**
   - **Monotonic Sequence Number:** Every report increments an integer sequence counter (`sequence_number`). The backend rejects any report where `sequence_number <= last_received_sequence`.
   - **Cryptographic UUIDv4 Report ID:** Every report receives a unique UUIDv4; duplicate report IDs are rejected with HTTP 409 Conflict.
   - **Timestamp Freshness:** Reports older than 5 minutes or more than 5 minutes in the future are rejected.

---

## 3. Operator Resource Protection

To ensure the agent does not impact the operator's internet experience or exceed monthly data allocations:

- **Daily Data Cap (`daily_data_cap_mb`):** Daily bandwidth consumption is tracked across a 24-hour UTC window. If the quota is exceeded, active tests are automatically skipped until the midnight UTC rollover.
- **Bandwidth Speed Throttling (`max_bandwidth_limit_mbps`):** Ensures tests do not consume the operator's full connection pipe.
- **Bounded Duration (`max_test_duration_sec`):** Speed tests are limited to short intervals (default 10s).
- **Persistent Spool Queue (`internal/spool`):** If the network drops or the backend is offline, reports are spooled locally up to `max_spool_reports` (default 500) and flushed with rate limiting once connectivity is restored.
