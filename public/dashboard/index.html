Node Operator Quick-Start Guide (Windows 10/11)

Set up your lightweight Go bandwidth node in under 2 minutes.

1

Initialize Node Identity & Wallet Pairing

Open Windows PowerShell in the project directory and bind your recipient EVM wallet address. This generates an Ed25519 cryptographic keypair and deterministic Node ID:

.\bandiq.exe init -wallet "0xYourWalletAddressHere"
2

Grant Explicit Operator Consent

In accordance with privacy standards, the agent will never touch your network until you record voluntary consent:

.\bandiq.exe consent -accept
3

Launch the Node Agent Daemon

Start the lightweight agent. It monitors physical interface octets via Windows IP Helper APIs without CGo dependencies:

.\bandiq.exe start
# Or using the automated background launcher:
.\scripts\run-node.ps1
4

Operational Power Controls

Proof-of-Bandwidth: The 10 Integrity Gates

Why a speed test alone does not equal token rewards. All evidence is verified before settlement.

Gate 1

Schema & Typing

Validates report structure, mandatory parameters, and software version compatibility.

Gate 2

Ed25519 Signatures

Validates cryptographic signature of report hash against registered node public key.

Gate 3

Sequence Monotonicity

Enforces strictly increasing sequence numbers per node ID to eliminate replay attacks.

Gate 4

Freshness Window (±5m)

Rejects expired or future-dated reports to eliminate delayed time-travel attacks.

Gate 5

Physical Bounds Check

Caps throughput at 10,000 Mbps and packet loss ≤ 100% to reject impossible metrics.

Gate 6

Hardware Counter Delta

Compares reported bytes against physical Windows network adapter octets (ΔIn + ΔOut ≥ Reported).

Gate 7

Identical Metric Spam

Detects synthetic scripts submitting identical throughput, latency, and jitter repeatedly.

Gate 8

Submission Rate Limit

Enforces a 30-second cooldown per node to prevent DDoS and spam on verifier nodes.

Gate 9

Traffic Segregation

Classifies speedtests as unearned CAPACITY_BENCHMARK and customer relay as BILLABLE_RELAY.

Gate 10

Statistical Vouchers

Computes confidence score (0-1.0). If ≥ 0.70 and billable traffic was served, issues signed voucher.

Bandwidth Marketplace & Settlement Flow

How consumers purchase bandwidth and providers earn BNDQ token settlement.

Phase 1

Service Request & Escrow

A customer specifies required volume (e.g. 10 GB) and escrows $BNDQ tokens in the settlement smart contract. Tokens are locked safely.

Phase 2

Workload Delivery & Mutual Receipts

Eligible nodes route traffic. Both customer and node sign cryptographically hashed byte-counter receipts during the session.

Phase 3

Verification & Voucher Issuance

The Verifier Service inspects mutual receipts, validates hardware counter telemetry, and issues a non-reentrant Settlement Voucher.

Phase 4

On-Chain BNDQ Settlement

The settlement contract on Sidra Chain checks the verifier signature and releases escrowed BNDQ tokens directly to the provider's wallet.

Privacy, Security & Ethical DePIN Tenets

  • No Open Relays or Botnets: The agent does not allow random, unauthenticated internet traffic to enter or exit your connection.
  • Zero Private Key Exposure: You never share your wallet private key or mnemonic phrase. Only public EVM addresses are associated.
  • No Remote Shell Execution: The agent will never execute arbitrary terminal commands or run executables sent by the backend.
  • Zero Browsing History Collection: No website URLs, DNS queries, payload contents, or personal files are accessed.
  • Shariah & Ethical DePIN Alignment: Rewards strictly reflect verified physical utility; zero speculative fabrications or token supply inflation.
